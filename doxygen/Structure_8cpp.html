Construct boolean conditions from level-sensitive (AsyncRow) rows by partitioning them into rows driving '0' (clearCond) and rows driving '1' (presetCond).

Because Slang's table conflict check (BitTrie) guarantees that '0'-output and '1'-output rows are mutually exclusive for any 2-state input/state combination, when both '0' and '1' rows exist (e.g. D or SR latches), they combine into a single enable condition (asyncCond = clearCond | presetCond) with dynamic value (asyncVal = presetCond). When only '0' or only '1' rows exist, asyncVal is a constant 0 or 1.

Classify sequential UDP truth table rows into synchronous (edge-sensitive) transitions and asynchronous (level-sensitive) transitions.

Sequential UDPs in hardware are modeled either as edge-triggered flip-flops (where edge-sensitive rows syncRows describe clocked transitions on the edge-sensitive port and level-sensitive rows asyncRows describe asynchronous clear/preset overrides on asynchronous control ports) or as level-sensitive latches (where only asyncRows are present).

Safe Filtering and Benign Hold Rules: Truth tables may include entries that do not produce active 2-state transitions and are skipped before lowering:

  • Unknown ('x') rows: Like combinational UDP lowering (skipUnsupportedCombinationalRow), sequential UDP lowering models transitions in 2-state i1 logic (matching MooreToCore's 2-state lowering rather than 4-state X propagation). In IEEE 1800-2017 Table 29-1, 'x' in inputs or state only matches literal unknown x (unlike '?', which matches 0, 1, or x) so it cannot trigger in 2-state logic, and 'x' next-state outputs have no 2-state value, so rows containing 'x' are skipped.
  • Explicit hold rows: Rows specifying '-' as next-state explicitly indicate retaining the current state (e.g. on inactive clock edges (10) : -). Because the lowered moore.procedure only assigns to the state variable when an active transition condition holds, the state variable naturally retains its value when no active transition matches.
  • Idempotent hold rows: Rows where next-state matches current state (state == output, e.g. steady-state hold rows 0 : 0 : 0 or 1 : 1 : 1) preserve state and do not create active transitions.

Structural Lowering Requirements: Pure level-sensitive UDPs (latches) have no structural restrictions beyond Slang's table validation. For edge-triggered UDPs, while IEEE 1800-2017 Section 29.6 syntactically permits arbitrary combinations of level-sensitive and edge-sensitive rows, lowering to a structured flip-flop procedure (with outer asynchronous clear/preset priority branches and an inner clocked data branch) requires surviving active transitions to satisfy:

  1. Well-formed edge transitions (guaranteed by Slang and asserted here): a. At most one edge transition per table row. b. Supported transition specifiers: each edge transition must specify a recognized 2-state edge token.
  2. Single edge-sensitive port: all active edge transitions must share the same edge-sensitive input port.
  3. No mixed sensitivity on edge-sensitive port: an input cannot have both edge and level sensitivity (in an edge-triggered model, all active level rows must specify '?' on the edge-sensitive port).
  4. Pure asynchronous control: in an edge-triggered UDP, level-sensitive (asynchronous clear/preset) rows must not depend on the current state q (all active level rows must specify '?' on state).
  5. Separation of asynchronous control and synchronous data: a. Asynchronous control ports (input ports with a '0' or '1' level in asyncRows) cannot also act as varying synchronous data inputs across syncRows. b. Synchronous transitions (syncRows) cannot be conditioned on active asynchronous control levels.

Yields data unless it is exactly Z, in which case yields X instead.

Per IEEE 1800-2023 Section 28.6's table 28-5 for three-state gates, a Z data input yields X on either the actively-driven or ambiguous-enable path. Known 0/1 data values pass through unchanged. For three-state gates this depends on the assumption that we collapse L to 0 and H to 1.
