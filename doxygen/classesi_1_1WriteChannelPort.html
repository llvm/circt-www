Detailed Description

A ChannelPort which sends data to the accelerator.

It has two modes: Sync and Callback, which cannot be used at the same time. The mode is set at connect() time. To change the mode, disconnect() and then connect() again.

◆ connect() [2/2]

void WriteChannelPort::connect ( DataFetchCallback fetch,
WriteErrorCallback onError,
const ConnectOptions & options = {} )
virtual

Connect in callback mode.

Throws if already connected, if either callback is null, or if frames of a windowed message written in sync mode haven't all been sent yet (reconnect in sync mode and flush() them first). Must not be called concurrently with connect() or disconnect() on another thread. Callbacks may be invoked from any thread, but never concurrently with each other, and must return quickly. Exceptions thrown by fetch are reported to onError; those thrown by onError propagate out of whichever call invoked it (e.g. notifyAsyncDataAvailable() or poll(); the accelerator's service thread logs them). They may call notifyAsyncDataAvailable() and disconnect() (and then connect()), but must not wait on another thread which uses the port.

Default implementation: the port calls fetch and writes what it returns with tryWriteSegmentedImpl() (so backends which override that for scatter-gather support receive messages as-is), until fetch returns nullptr or the backend backpressures. It does so from notifyAsyncDataAvailable() and from poll() (e.g. called by the accelerator's service thread via AcceleratorServiceThread::addPoll()), which also retries the one fetched message the backend didn't accept. Each call writes at most kMaxAsyncWritesPerCall messages, so that it returns even if fetch always has data; poll() writes the rest. fetch is first called by the first of either after connecting. Its state is only allocated while it is in use.

Backends which override this must also override notifyAsyncDataAvailable(), uphold the callback contracts, and call connectCallbackMode().

bool esi::WriteChannelPort::tryWrite ( const MessageData & data)
inline

A basic non-blocking write API.

Returns true if any of the data was sent; false means none of it was, and the write should be retried. If the data type is a window a 'true' return does not indicate that the message has been completely written. The 'flush' method can be used to check that the entire buffer has been written. It is invalid for backends to always return false (i.e. backends must eventually ensure that writes may succeed).
